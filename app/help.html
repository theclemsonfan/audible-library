NEXT CHAPTER · 0.2.0 DEPLOYMENT CANDIDATE

Everything in one package.

The audiobook app, its private server, and the automated desktop companion. Start with a local check, then deploy the same server under HTTPS for your phone.

What is—and is not—finished.

The server and import connection are implemented. Automated tests and synthetic-page checks pass. Your actual Audible account, desktop extension installation, and chosen hosting environment still need their first live validation. No website or private library was changed by preparing this package.

1. Open the app on your desktop

Extract the complete ZIP into a permanent folder. A current Node.js 24 LTS installation is the only prerequisite for local mode. There are no runtime packages to install and no AI API keys.

Windows: double-click START-WINDOWS.cmd.
Mac: use START-MAC.command. A terminal alternative, from the extracted folder:

node scripts/start-local.mjs

The launcher opens first-time setup with its one-use key. Choose a new Next Chapter password. This is not your Amazon password. Keep the server window open while syncing.

The local address is:

http://localhost:8787

Localhost is deliberately private to this computer. Your iPhone cannot reach that address on another device. For phone access, deploy the included server under HTTPS as explained below.

2. Load the desktop companion

In Chrome, open:

chrome://extensions

Or, in Brave:

brave://extensions

Enable Developer mode → Load unpacked. Select the package’s extension folder, which contains manifest.json. Keep this folder in place afterward. This is a developer build, not a Web Store installation.

3. Pair it once and collect your library

In Next Chapter, open Sync & settings → Generate pairing code. The app provides separate Copy buttons for the app address and code. Open the companion extension, paste those into the labeled fields, and select Pair browser. Approve access to your own app origin.

Sign in to Audible normally in that same desktop browser profile. Select Sync now. The extension creates its own background tab. It reads library pages, purchase/refund history, recent listening history, and optional series pages. Leave that scan tab alone. You can close the extension popup.

Look for a real last successful sync and title count in the app. Incomplete scans do not overwrite a good library. If Audible asks for verification, collection pauses; it does not bypass the check.

4. Let the browser handle weekly updates

Automatic sync is enabled by default. It checks for the Sunday-morning run about hourly and catches up after the browser is reopened. Progress checkpoints survive interruptions. The computer must be awake and Chrome or Brave running. No ChatGPT window is required.

Archived-item inclusion is still unverified. Recent web listening history is not the full listening log. Ownership, unfinished status, and listening progress are preserved separately; missing or ambiguous data are not invented.

5. Deploy the full app for your iPhone

This build includes Dockerfile, compose.yaml, compose.https.yaml, Caddyfile, and .env.example. Use an existing Docker-capable host with persistent disk and a real HTTPS hostname. Set PUBLIC_URL and APP_DOMAIN to your own address in a private .env file. This is not a static-only deployment, and no hosting service or domain has been bought.

After the host and DNS are configured:

docker compose -f compose.yaml -f compose.https.yaml up -d --build

Read the first-time setup key in your own server terminal:

docker compose exec app cat /app/data/setup-key.txt

Open your actual HTTPS app address, complete setup, and pair the desktop companion to this hosted address. On iPhone, open it in Safari and use Share → Add to Home Screen.

The earlier ChatGPT-hosted preview has not been replaced. Deploy this complete package to get the new shared database and sync backend. The deployment and first account sync are the final acceptance steps, not something already completed.

Built-in checks and recovery

From the extracted folder:

npm run check
npm test

To probe a running local server without using account data:

node scripts/verify-deployment.mjs http://localhost:8787

Keep the private data directory or Docker volume. Ten consistent snapshots rotate before successful imports replace an existing inventory. They are on the same host—not off-site backups. Never upload the data directory to GitHub, and never delete the Docker data volume when upgrading.

Full operating, backup, troubleshooting and security notes are included in docs/DEPLOYMENT.md, docs/PRIVACY_AND_SECURITY.md, and docs/VALIDATION.md.
